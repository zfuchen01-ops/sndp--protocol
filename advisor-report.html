B2：卫星回传瓶颈发现协议
端口监测 → 距离矢量传播 → 终端感知 — NS-3 协议实现与验证

协议做什么

B2 协议解决什么问题：卫星网络中，用户选择接入卫星时只看空口信号强度，不知道这颗星的回传链路（星间+馈电）还剩多少容量。大量用户"不约而同"涌向同一颗信号好的星，瞬间拥塞。

B2 怎么做：每颗卫星实时监测自己的 ISL/馈电端口流量（队列字节计数器），算出剩余可用带宽，通过 PUSH/REQUEST/REPLY 三种轻量消息在卫星间逐跳传播瓶颈值，最后通过 ADV 广播给覆盖区内所有终端。终端据此做出"回传容量可感知"的接入选择。

三句话概括：端口监测 → 距离矢量传播 → 终端感知。

消息语义与状态机

Type含义触发条件行为
PUSH (0)主动推送端口流量变化 ≥ 阈值向所有邻居推送当前 GS 瓶颈表
REQUEST (1)初始拉取卫星启动向所有邻居请求 GS 瓶颈表
REPLY (2)按需回复收到 REQUEST单播回复当前 GS 瓶颈表

处理规则 — 逐跳 min 瓶颈 + Split Horizon

收到 PUSH/REPLY (来自邻居 N, 含GS条目 G):
  if N ≠ 本卫星到 G 的路由下一跳 → 忽略 (路由对齐)
  if G 是直连 GS → 忽略 (本地权威)
  newBw = min( 本卫星→N的可用带宽 , N通告的瓶颈 )
  if newBw > m_gs[G]:
    m_gs[G] = newBw
    m_gsSource[G] = N           ← 记录来源
    触发 PUSH 给其他邻居 (Split Horizon: 不推回给 N)

可用带宽计算 (每200ms):
  avail = 链路容量 − (队列GetTotalReceivedBytes() delta / dt)
  → 真实端口监测, 非静态配置

错误处理

错误行为
Magic ≠ 0x4232静默丢弃
Version ≠ 1静默丢弃 (未来版本向前兼容)
Type ∉ {0,1,2}静默丢弃
TTL = 0丢弃 (防环, 不转发)
TotalLength ≠ 实际包长丢弃
REQUEST 无响应 (1s超时)重发 ×3, 仍无→标记邻居不可达

N2 接口 — gNB↔Router (星内本地)

同一颗卫星内部, 127.0.0.1:9998
gNB → Router: [0x00] (1B trigger)
Router → gNB: [N(1B)] [for each GS: bw(4B) name_len(4B) name desc_len(4B) desc]
