SBDP：卫星回传瓶颈发现协议
全层 SbdpHeader (16B+TLV+CRC) · ISL·N2·ADV 统一 — NS-3.42 实验验证

协议做什么

SBDP 协议解决什么问题：卫星网络中，用户选择接入卫星时只看空口信号强度，不知道这颗星的回传链路（星间+馈电）还剩多少容量。大量用户"不约而同"涌向同一颗信号好的星，瞬间拥塞。

SBDP 怎么做：每颗卫星实时监测自己的 ISL/馈电端口流量（DropTailQueue::GetTotalReceivedBytes 计数器），算出剩余可用带宽，通过 SbdpHeader SBDP_LINK_PROBE/SBDP_CAPACITY_REQ/SBDP_CAPACITY_ACK 在卫星间逐跳传播瓶颈值。gNB 汇总后，通过 SbdpHeader::BuildAdv() (SBDP_CAPACITY_ADV) 广播给覆盖区内所有终端。ISL·N2·ADV 三层面统一使用 SbdpHeader (16B+TLV+CRC)。终端据此做出"回传容量可感知"的接入选择。

三句话概括：端口监测 → 距离矢量传播 → 终端感知。

协议设计

报文结构 — SbdpHeader (sbdp-header.h, 全层统一)

  ISL·N2·ADV 三层面共用同一 SbdpHeader 格式，仅 Type 字段区分场景。

    0         1         2    3         4    5       6       7
  ┌─────────┬─────────┬─────────────┬─────────────┬───────┬───────┐
  │Ver(4)│Type(4)│  Flags(8)    │   TotalLen(16)│SeqNum(16)│TTL(8)│Hop(8)│
  │  =1   │见下表  │  0x00       │  自描述      │去重     │20    │跳数   │
  ├─────────┴─────────┼─────────────┴─────────────┼───────┴───────┴───────┤
  │ Backhaul Capacity (float32, Mbps)              │CRC-16(16)│Reserved(16)│
  │ (当前回传瓶颈，ISL min-hop 逐跳更新)              │  CCITT   │            │
  ├────────────────────────────────────────────────┴──────────┴────────────┤
  │ TLV Options: Type(2B)+Len(2B)+Value                                    │
  │ ISL: SOURCE_ID · BOTTLENECK_LINK · GS_BOTTLENECK                       │
  │ N2: 同上 + LINK_LATENCY · LINK_JITTER · LINK_PKT_LOSS                  │
  │ ADV: SOURCE_ID · DEST_ID · BOTTLENECK_LINK · TIMESTAMP · VALIDITY_PERIOD│
  └───────────────────────────────────────────────────────────────────────┘

  固定头 (金色): Ver|Type·Flags·TotalLen·SeqNum·TTL·Hop·BackhaulBw·CRC·Reserved = 16B
  TLV 链 (蓝色): 按需附加 — ISL 只需 SOURCE_ID + BOTTLENECK_LINK，ADV 加 TIMESTAMP
  核心: BackhaulBw float32 嵌在固定头，每跳 min() 更新，CRC 每跳重算

  最小包: REQ = 16B (无TLV) | 典型 PROBE/ACK = 52B (SOURCE+BOTTLENECK+GS_BOTTLENECK TLV)
  CRC-16-CCITT 多项式 0x1021, 初值 0xFFFF, 覆盖前 14 字节
校验
CRC-16-CCITT
每跳重算, 比特翻转检测
防环
TTL + HopCount
TTL=20, 逐跳−1, 归零丢弃

消息类型 — 6 种，覆盖三层

Type名称层面触发行为
PROBE (0x4)ISL 推送星间端口流量变化 ≥ 阈值每 GS 一条→所有邻居 (one per GS)
REQ (0x2)ISL/N2 请求星间+星内卫星启动 / gNB 查询16B 最小包→邻居或 Router
ACK (0x3)ISL/N2 应答星间+星内收到 REQ每 GS 一条→请求方
ADV (0x1)容量通告gNB→UEN2 更新后BuildAdv()→广播给覆盖区所有 UE
MIGRATE (0x5)N3 迁移星间协同gNB 过载源gNB→目标gNB: UE_LIST + RESERVED_BW
CONFIRM (0x6)N3 确认星间协同收到 MIGRATE目标gNB→源gNB: ACCEPT / REJECT

处理规则 — RemoveHeader + TLV 解析

ISL 接收 (SatRouter::RecvEx):
  SbdpHeader h;
  pkt->RemoveHeader(h);                    // NS-3 框架自动 CRC 校验 + 反序列化
  uint8_t type = h.GetMsgType();
  std::string nbName = h.GetSrcNode();     // SOURCE_ID TLV → 发送方
  float nbBw = h.GetBackhaulBw();          // 固定头 float32 → 瓶颈值
  std::string gs = h.GetBottleneckLink();  // BOTTLENECK_LINK TLV → GS 名

  if (type == SBDP_CAPACITY_REQ) { SendReply(nbName); }
  else if (type == SBDP_LINK_PROBE || type == SBDP_CAPACITY_ACK) {
    // 路由对齐 + Split Horizon
    if (m_nexthop[gs] != nbName) continue;
    if (m_nexthop[gs] == "") continue;     // 直连 GS → 本地权威
    double newBw = min(nbLink, nbBw);
    if (newBw != m_gs[gs]) { m_gs[gs] = newBw; propagated = true; }
  }

ISL 发送 (SatRouter::SendPush):
  for each GS:  // 每 GS 一个独立 SbdpHeader 消息
    SbdpHeader h = SbdpHeader::BuildIslPush(myName, gsName, bw, seq++);
    pkt->AddHeader(h);                     // NS-3 框架自动序列化 + CRC
    for each neighbor: m_sk->SendTo(pkt, ...);

可用带宽 (每 200ms): avail = cap − (Queue::GetTotalReceivedBytes delta / dt)

错误处理

错误行为
CRC-16-CCITT 校验失败静默丢弃 (RemoveHeader 自动检测)
Version ≠ 1静默丢弃
Type ∉ {1,2,3,4,5,6}静默丢弃
TTL = 0丢弃 (防环), 默认 TTL=20
TotalLength 不匹配丢弃 (RemoveHeader 自动校验)
REQ 无响应 (1s超时)重发 ×3, 仍无→标记邻居不可达

N2 接口 — gNB↔Router (星内本地, SBDP_CAPACITY_REQ/ACK)

同一颗卫星内部, 127.0.0.1:9998
  gNB → Router: [0x00] (1B trigger)
  Router → gNB: BuildN2Ack() × N_GS 条 SBDP_CAPACITY_ACK
    每条: 固定头 backhaulBw=float32(该GS瓶颈)
          TLV: SOURCE_ID | BOTTLENECK_LINK | GS_BOTTLENECK
  gNB: RemoveHeader(h) → GetBottleneckLink()+GetBackhaulBw()
       → BuildAdv() → 广播给覆盖区内所有 UE

  N3 接口 — gNB↔gNB (星间协同, sbdp-n3-handover.cc):
  ┌──────────────┬──────┬──────┬──────┬────────────────┐
  │ Type(1B)=0x5/0x6 │ueCnt│ Seq  │ResBw │ payload[64B]  │
  ├──────────────┴──────┴──────┴──────┴────────────────┤
  │ MIGRATE (0x5): 源gNB→目标gNB "请求接收N个UE"     │
  │ CONFIRM (0x6): 目标gNB→源gNB "ACCEPT" 或 "REJECT" │
  └────────────────────────────────────────────────────┘

信令开销 — 事件驱动, 稳定期零流量

SBDP 信令不是周期心跳，是端口计数器变了才发。 卫星 monitor 队列 → 变化超阈值 → 触发 push。无变化时 ISL 零流量。固定头仅 16B，典型消息 ~52B。Split Horizon 削减冗余转发 (12星实验: 100s 仅 31 条)。
对比 OSPF: OSPF Hello 每 10s 周期洪泛，SBDP 稳定期不需要任何消息——事件驱动比周期心跳更省带宽。

辅助实验四 — SBDP 回传感知驱动的 Transformer 切换决策

问题：SBDP 协议让终端感知回传瓶颈。但如果终端沿用传统 MGCS（选最强信号），B2 信息就被浪费了。能否用 RL 智能体学习利用 SBDP 回传信息，做出更聪明的切换？

方案：将 SBDP 提供的 ISL/馈电可用带宽作为 RL 状态特征，训练 Transformer Q-Network（TF4）学习切换策略。与五种基线对比：MGCS（最强信道）、ELEV（最高仰角）、MRVT（最小跳数）、MINL（最小负载）、RAND（随机）。
